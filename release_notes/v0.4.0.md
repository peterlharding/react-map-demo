# React Map Demo 0.4.0

This release adds a fifth demo, Add Places, which moves from tracking one marker to keeping a whole list of them in React state.
It also introduces the first info windows, and makes marker dragging and focus outlines behave consistently across every demo.

## Highlights

- **New demo: Add Places (`/add-places`).**
  Click the map to drop numbered places, which are listed beside the map (below it on narrow screens).
  Click a marker or a list entry to open an info window with the place's coordinates and a Remove button; choosing from the list also pans the map to the place.
  Drag a marker to move its place, and remove places one at a time or all at once with Clear all.
  Clicking one of Google's own points of interest adds a place there instead of opening Google's information popup.
- **Focus outlines for keyboard users only, everywhere.**
  Google Maps moves focus after mouse use as well as keyboard use, for example into an info window as it opens, which made buttons look already selected.
  Focus outlines on maps, markers and info window buttons now appear only after the keyboard is used, extending the marker fix from 0.2.1.

## Upgrading

Nothing is required.
Places added in the new demo are not saved, so reloading the page starts with an empty list.

## Under the hood

- `AdvancedMarker` gains `label` (white text on the pin), `title` and `onClick`.
  Click handling turns on `gmpClickable`, without which this version of the Maps API never sends `gmp-click`.
- Releasing a dragged marker also sends the map a click, delivered about 300 ms later once Google has ruled out a double click.
  The new `markerDrag.ts` records when each drag ends, and `MapCanvas` drops the click from the same gesture, so a drag can never add a place or open a popup on any demo.
- The new `inputModality.ts` records whether the mouse or keyboard was used last as `data-input-modality` on the page, and replaces the marker-specific workaround from 0.2.1.
- `MapCanvas` accepts `onClick` and `onLoad`, and its documentation explains why `center` should be a stable value.
- The places list is a real `<ul>` list labelled "Places", so screen readers announce it as one.
- Tests cover adding, showing, removing and clearing places, the drag click filter and the input tracking, using `@testing-library/user-event`.
